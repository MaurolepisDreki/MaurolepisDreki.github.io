Normally, one would start with <q>Day 1</q>, after all, it is impossible for something to exist that does not have an origin.&nbsp; But (as is often the case) Day 1 came and went as simply getting the prelimaries of this project set up &mdash; lit. learning which versions of Ruby are available for my system(s), how far behind the maintaners are behind the Ruby repository, if the Jekyll gem is compatible with the distributed and current versions, if the ROI is worth building Ruby from source (again), updating `gem`, updating all my gems, installing the `jekyll` gem, setting up a simple Jekyll site, figuring out how to custom theme it, realizing that `new-theme` was for creating reusable themes instead of one-off themes specific to only this weblog, deleting everything and then restarting the project as a `--blank` Jekyll site before finally updating the EoL `@include` Sass-tag in the `assets/css/main.scss` file to refelct the current standard of using the `@use` Sass-tag (per the warning).&nbsp; And that's all that got done on Day 1 &mdash; <span class="highlight">a typical Day 1 on a brand-new in this developer's experiance.</span>

Day 2, however, has been more fulfilling.&nbsp; Today we have started adding layouts and content (this weblog entery, specifically), including the essential formatting required for navigation bar, `#navbar`, which is always like going for a roller-coaster ride on broken rails...

I always remember, about this point, how much I hate modern HTML, and CSS, and even Markdown.&nbsp; JavaScript got a little better by use of CDNs and browser APIs, but tying to layout pages using nothing but flexboxes, node selectors, and conflicting formatting markers &mdash; using only abstract CSS and untabulated HTML?&nbsp; Gods, kill me now!&nbsp; And also whomever thought that doing things this way was a good idea.&nbsp; They were clearly not a developer.
